## 真实 score 服务骨架接入结果分析

在前一阶段工作中，项目已完成基于启发式 mock score 服务的二级验证增强实验，并证明了二级 score 在自动 fuzz 场景下能够产生稳定的额外筛选作用。为进一步向真实 SE-fAnoGAN-ES 接入过渡，本阶段在保持现有 socket 协议、`nv_body_valid.py` 调用方式以及主实验框架不变的前提下，构建了基于“特征抽取层 + 离线评分层”的在线 score 服务骨架。具体而言，首先设计并实现了 `feature_extract.py`，用于将规范化后的 JSON body 转换为固定维度数值特征向量；随后实现 `score_json_offline.py`，用于基于提取到的结构特征、字符串异常特征、列表重复度特征和接口相关字段特征生成离线异常分数；在此基础上，进一步实现在线服务骨架 `nv_valid_server_real.py`，使系统能够通过 UNIX socket 接收 JSON body、完成特征提取和离线评分，并按现有 score RPC 协议返回浮点分值。

为了验证该在线服务骨架是否能够在现有 fuzz 实验链路中稳定工作，采用最小 AFL 批量实验进行了验证。实验中将二级 score 服务切换为 `nv_valid_server_real.py`，继续沿用 `cms_doc_list` 接口、敏感种子目录 `in/o2oa_body_cms_score/` 和 score 阈值 `1.5`。结果表明，在短时 AFL 驱动批量实验中，共有 `109` 个样本通过一级规则并进入真实 score 服务骨架，其中 `63` 个样本通过二级 score，`46` 个样本被二级 score 拒绝，同时 `body_score_rpc_ok = 109`、`body_score_rpc_fail = 0`。这说明该在线服务骨架不仅能够在单次手工请求场景下稳定返回分值，而且已经能够在 AFL 驱动的连续批量请求场景下保持正常工作，并对通过一级规则的样本产生有效的 pass / reject 分层结果。

从研究意义上看，这一结果表明当前项目已经完成了从“启发式 mock score 服务”向“特征驱动在线 score 服务骨架”的关键过渡。也就是说，二级验证模块的后端已经不再仅依赖单文件启发式打分逻辑，而是升级为“JSON body → 特征抽取 → 异常评分 → 在线返回分数”的分层结构。这为后续真实 SE-fAnoGAN-ES 接入奠定了直接基础。后续工作中，无需改动现有 socket 协议、harness 逻辑、规则配置和实验脚本，只需将 `nv_valid_server_real.py` 中当前调用的离线评分函数 `score_from_features(feat)` 进一步替换为真实 SE-fAnoGAN-ES 模型推理过程，即可完成真实模型后端的平滑接入。因此，本阶段的结果可以视为“真实 SE-fAnoGAN-ES 接入前的在线服务骨架已验证完成”，标志着项目下一阶段已经从单纯框架搭建正式进入到模型后端替换与智能评分能力增强阶段。
