# 模糊测试模块新平台接入说明

## 1. 接入原则

新增平台时，优先新增平台 profile，不改适配层主流程。

建议新增内容：

1. 一个新平台 profile；
2. 一组最小正常 seed；
3. 一份平台适配说明；
4. 必要的 runner template；
5. 必要的结果映射说明。

不建议新增：

- 新的 AFL++ 主链逻辑；
- 新的复杂调度系统；
- 独立数据库；
- 与现有 runner 平行的第二套任务系统。

## 2. 新平台 profile 最小字段

profile 文件建议放在：

```text
integration/platform_profiles/<new_profile>.json
```

最小字段：

```json
{
  "profile": "new_platform_profile",
  "platform": "NewPlatform",
  "scene": "target_scene",
  "target_type": "http_api",
  "target_endpoint": "target endpoint",
  "seed_dir": "in/new_platform_seed_dir",
  "model_route": "platform model route",
  "model_name": "model name used by runner",
  "threshold": "threshold value",
  "manifest": "model_stage/manifests/new_platform_manifest.txt",
  "template": "runner/templates/task_new_platform.json",
  "duration_plan": [20, 60],
  "is_mainline": false,
  "validation_scope": "minimum validation scope",
  "description": "profile description",
  "result_description": "expected report files",
  "model_files": [
    {
      "name": "model",
      "path": "model_stage/models/new_platform_model.pt",
      "required": true
    },
    {
      "name": "meta",
      "path": "model_stage/models/new_platform_meta.json",
      "required": true
    }
  ]
}
```

## 3. 新平台接入步骤

### 第一步：准备最小 seed

放入：

```text
in/<new_platform_seed_dir>/
```

要求：

- 至少包含可被目标平台接受的正常请求样本；
- 文件格式与平台 runner template 约定一致；
- seed 目录路径写入 profile 的 `seed_dir`。

### 第二步：准备 manifest

放入：

```text
model_stage/manifests/<new_platform_manifest>.txt
```

manifest 应与模型训练、验证、交付说明中的样本口径一致。

### 第三步：准备模型与 meta

放入：

```text
model_stage/models/
```

profile 的 `model_files` 必须列出模型和 meta 路径，适配器会在 `submit --dry-run` 中做存在性检查。

### 第四步：准备 runner template

放入：

```text
runner/templates/task_<new_platform>.json
```

template 中应继续使用现有 runner 可识别字段，例如：

- `target_type`
- `seed_dir`
- `model_name`
- `threshold`
- `manifest`
- `duration_plan`
- `launch_cmd`
- `result_summary_csv`
- `result_stats_json`

### 第五步：静态链路验证

执行：

```bash
python3 integration/fuzz_adapter.py profiles
python3 integration/fuzz_adapter.py submit --request-json <new_submit_request.json> --dry-run
```

静态链路验证通过后，再进入组件联调。

## 4. 结果归一化要求

新平台优先复用现有 runner 报告路径：

- `runner/tasks/<task_id>/status.json`
- `runner/tasks/<task_id>/report.json`
- `runner/runs/<task_id>/summary_dur20.csv`
- `runner/runs/<task_id>/summary_dur60.csv`
- `runner/runs/<task_id>/body_valid_stats_dur20.json`
- `runner/runs/<task_id>/body_valid_stats_dur60.json`

只要底层 runner 能生成上述结果，适配器就可以通过 `query` 和 `report_query` 做统一输出。

## 5. 联调检查清单

新平台接入时至少检查：

- profile 能被 `profiles` 加载；
- `submit --dry-run` 中 template、seed、manifest、model、meta 都存在；
- `submit` 能生成 runner task；
- `query` 能返回统一任务状态；
- `stop` 能控制任务；
- `report_query` 能返回标准报告列表；
- 文档中明确该平台是主线、增强路线还是最小校准验证。
