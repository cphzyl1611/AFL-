# 模糊测试模块集成完成说明

## 1. 集成目标

本轮已为模糊测试模块新增仓库内集成适配层，用于总工具统一调用。该适配层聚焦任务调度适配、平台 profile、结果归一化和组件联调，不改变已验收通过的 O2OA / Flowable 最终技术口径。

## 3. 调用方式

统一入口：

```bash
python3 integration/fuzz_adapter.py <action> --request-json <request.json>
```

统一动作：

```bash
python3 integration/fuzz_adapter.py submit --request-json docs/integration/examples/fuzz_submit_o2oa.json
python3 integration/fuzz_adapter.py query --request-json docs/integration/examples/fuzz_query.json
python3 integration/fuzz_adapter.py stop --request-json docs/integration/examples/fuzz_stop.json
python3 integration/fuzz_adapter.py report_query --request-json docs/integration/examples/fuzz_report_query.json
```

统一输出：

- `process_result`
- `action`
- `task_id`
- `query_description`
- `total_count`
- `report_list`
- `download_url`

## 4. 换平台方法

O2OA：

```json
{
  "platform": "o2oa_default"
}
```

Flowable：

```json
{
  "platform": "flowable_v2"
}
```

调用方只改 `platform` 和必要的 `target_endpoint`、`seed_location`，不改 `submit / query / stop / report_query` 主流程。

## 5. 新平台接入方法

未来新增平台时，优先按以下方式接入：

1. 新增 `integration/platform_profiles/<new_profile>.json`；
2. 准备 `in/<new_platform_seed_dir>/`；
3. 准备对应 manifest；
4. 准备必要模型和 meta；
5. 准备 runner template；
6. 使用 `submit --dry-run` 做静态链路验证；
7. 再进入组件联调。

适配层主流程不需要因新增平台而改动。

## 6. 已完成验证

已完成静态与最小链路验证：

- `integration/fuzz_adapter.py` Python 语法检查通过；
- `profiles` 能加载 `o2oa_default` 与 `flowable_v2`；
- 两个平台 profile JSON 可解析；
- 示例请求 JSON 可解析；
- O2OA `submit --dry-run` 能把统一请求映射为 runner task，并检查 template、seed、manifest、model、meta 均存在；
- Flowable `submit --dry-run` 能把统一请求映射为 runner task，并检查 template、seed、manifest、model、meta 均存在；
- `query` 已用历史 Flowable v2 task 验证统一状态查询输出；
- `stop --dry-run` 已验证停止链路存在，不发送实际停止信号；
- `report_query --no-refresh` 已验证报告查询和结果归一化输出。

## 7. 当前限制与后续联调建议

本轮未执行真实 O2OA / Flowable submit smoke，因为真实执行依赖运行环境：

- O2OA 需要可用的 O2OA 目标、`NV_TOKEN`、AE score service；
- Flowable 需要可用的 Flowable REST 服务、Flowable-AE v2 score service；
- 真实 submit 会启动底层 runner 与执行脚本，当前阶段不重跑大型实验。

后续组件联调建议：

1. 先启动对应 score service；
2. 确认 O2OA 或 Flowable 目标服务可达；
3. 用 `submit --dry-run` 复核 profile 映射；
4. 再执行一次短时真实 `submit`；
5. 用统一 `query / stop / report_query` 完成联调闭环。

## 8. 最终结论

模糊测试模块集成适配层已形成。当前已经具备统一任务下发、查询、停止、报告查询能力，支持 `o2oa_default` 与 `flowable_v2` 两个平台 profile，并完成结果归一化和静态链路验证。真实运行级 smoke 仍需在目标服务和 score service 可用时进行组件联调。
