# 模糊测试模块集成说明

## 1. 集成目标

本集成适配层用于把已验收通过的模糊测试模块封装成总工具可统一调用的组件能力。当前目标是组件集成、任务调度适配、结果归一化和组件联调，不改变已收口的模糊测试主线技术口径。

统一动作包括：

- 任务下发：`submit`
- 任务查询：`query`
- 任务停止：`stop`
- 报告查询：`report_query`

当前支持的平台 profile：

- `o2oa_default`
- `flowable_v2`

换平台方式固定为：调用方只改请求 JSON 中的 `platform` 字段和必要的场景、seed 参数，不改主调用流程。

## 2. 实现方式

新增适配器：

- `integration/fuzz_adapter.py`

新增平台 profile：

- `integration/platform_profiles/o2oa_default.json`
- `integration/platform_profiles/flowable_v2.json`

适配器不重写 fuzz 引擎，不修改 AFL++ 主链，底层继续复用：

- `runner/fuzz_test_runner.py`
- `runner/templates/task_ae_default.json`
- `runner/templates/task_ae_flowable_eval_v2.json`
- `runner/tasks/`
- `runner/runs/`
- 现有 `docs/final_results/` 与 `docs/final_delivery/`

## 3. 当前 profile 口径

### o2oa_default

- 平台：O2OA
- 场景：`cms_doc_list`
- 目标类型：`http_api`
- 默认 seed：`in/o2oa_body_model_compare`
- 默认模型路线：AE default, baseline_156
- 默认阈值：`1.0`
- 默认 manifest：`model_stage/manifests/dataset_manifest_156.txt`
- 默认模板：`runner/templates/task_ae_default.json`
- 定位：主线 profile

### flowable_v2

- 平台：Flowable
- 场景：process start
- 目标类型：`http_api`
- 默认 seed：`in/flowable_process_start_dataset_v2`
- 默认模型路线：Flowable-AE v2 minimum-calibration route
- 默认阈值：`6.3`
- 默认 manifest：`model_stage/manifests/flowable_manifest_90.txt`
- 默认模板：`runner/templates/task_ae_flowable_eval_v2.json`
- 定位：第二平台最小校准验证 profile，不表述为完整第二平台 AFL++ 变异模糊测试主链

## 4. 结果归一化

适配器对外输出统一 JSON，核心字段包括：

- `process_result`：`1` 表示处理成功，`0` 表示处理失败
- `action`：当前动作
- `task_id`：对外任务 ID，格式为 `fuzz-task-<runner_task_id>`
- `query_description`：任务查询摘要
- `total_count`：报告数量
- `report_list`：报告列表
- `download_url`：当前仓库内报告路径

底层 runner 的原始字段会保留在 `runner_status`、`decision_summary`、`artifacts` 等字段中，便于总工具进一步展示或归档。

## 5. 边界

本集成适配层不做以下事情：

- 不新增 AFL++ 主链能力；
- 不改变 O2OA 默认 AE@1.0 口径；
- 不改变 GAN v2 研究增强路线；
- 不改变 Flowable-AE v2@6.3 最终口径；
- 不引入数据库、前端或完整网关服务；
- 不重跑大型实验。
