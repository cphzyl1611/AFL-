# 接口能力审计报告

日期：2026-05-10

本报告仅依据仓库已有配置、脚本、profile、结果文件和审查文档整理接口能力边界；不包含 token，不包含访问命令，不包含 fuzz 执行命令，不把 adapter demo 作为真实模糊测试证据。

## 1. 项目文件要求的接口类型

项目文件体现出的接口测试要求集中在 HTTP/REST JSON API，重点面向电子政务系统关键业务接口和数据处理路径。现有实现以 body-only JSON fuzz 为主，即在保持 HTTP method、path、认证上下文和基础请求结构的前提下，对 JSON body 做结构保持型变异、规则校验、评分过滤和统计输出。

从 `targets/o2oa_query.json`、`nv_http_harness.py`、`nv_body_valid.py`、`nv_json_mutator.py`、`integration/fuzz_adapter.py`、`runner/fuzz_test_runner.py`、`integration/platform_profiles/o2oa_default.json`、`integration/platform_profiles/flowable_v2.json` 等文件看，项目要求支持以下能力：

| 要求项 | 项目文件中的体现 | 当前理解 |
| --- | --- | --- |
| 电子政务关键业务接口 | `targets/o2oa_query.json`、`validity/o2oa_query_rules.json` | 以 O2OA CMS、公文/数据查询类接口为主线场景 |
| HTTP/REST JSON API | `nv_http_harness.py`、`targets/o2oa_query.json`、`flowable_v2.json` | 以 JSON request body 为主要变异对象 |
| body-only 结构保持型模糊测试 | `nv_json_mutator.py`、`nv_body_valid.py` | 通过 JSON 结构变异、规则过滤和评分过滤控制有效输入比例 |
| O2OA 电子公文数据接口 | `cms_doc_list` 配置、O2OA profile、真实 smoke 结果 | 当前主线已落到 CMS document filter/list |
| 任务下发字段 | `integration/fuzz_adapter.py`、`runner/fuzz_test_runner.py`、`runner/templates/*.json` | 支持 `target_type`、`target_endpoint`、`seed_source`、`seed_location`、`mutation_scope`、`max_test_cases`、`time_budget` 等 runner/adapter 级字段 |
| baseline / rule_only / rule_score | `scripts/run_cms_body_valid_compare_real.sh`、O2OA summary | 支持三种对照模式，用于比较无规则、规则过滤、规则+评分过滤效果 |
| 有效性验证与二阶段判定 | `nv_body_valid.py`、`model_stage/nv_valid_server_real.py`、`integration/decision_engine.py` | 支持规则、AE、GAN 或 Flowable 本地规则作为有效性判定链路组件 |
| 执行监控与统计报告 | `fuzzer_stats`、`eval_report.json`、`summary.csv`、`plot_data` | 支持 Cov/Err/Rec 相关字段、HTTP 状态、body 规则和评分统计 |
| 平台任务语义 | `integration/fuzz_adapter.py`、`runner/fuzz_test_runner.py`、`docs/integration/模糊测试模块调用说明.md` | 当前是 runner/adapter 级 submit/query/stop/report_query 语义，不是完整 HTTP/RPC 网关 |

## 2. 当前已验证接口

当前仓库中能够用已有 evidence 支撑的真实服务接口只有 O2OA 主线接口和 Flowable 支线接口。adapter demo 只能证明任务语义，不计入真实接口模糊测试证据。

| 接口名称 | 平台 | method | path | 配置/Profile | 种子与规则 | 关联脚本 | 结果证据 | 当前状态 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| CMS document filter/list | O2OA | PUT | `/x_cms_assemble_control/jaxrs/document/filter/list/1/size/5` | `targets/o2oa_query.json`、`integration/platform_profiles/o2oa_default.json` | `in/o2oa_body_cms_score`、`in/o2oa_body_model_compare`、`validity/o2oa_query_rules.json` | `scripts/run_cms_body_valid_compare_real.sh` | `out/cms_body_valid_compare_real/summary.csv`、`out/real_service_smoke_20260508/o2oa_real/summary.csv`、`docs/review/真实服务环境smoke验证报告.md` | 真实服务 smoke 已通过，主线接口 |
| Process instance start | Flowable | POST | `/flowable-rest/service/runtime/process-instances` | `integration/platform_profiles/flowable_v2.json` | `in/flowable_process_start_dataset_v2`、`flowable_rule_v1` | `scripts/run_flowable_process_start_compare.py`、`scripts/run_runner_flowable_plan.sh` | `out/real_service_smoke_20260508/flowable_dur20/summary.csv`、`out/real_service_smoke_20260508/flowable_dur60/summary.csv`、`docs/review/真实服务环境smoke验证报告.md` | 真实服务最小 smoke 已通过，支线接口；口径为 `python_static_loop / flowable_min_calibration`，不是完整 AFL++ mutation-chain |

O2OA 主线证据显示 `baseline`、`rule_only`、`rule_score` 三种模式均有真实服务结果，其中 `rule_score` 具备评分服务参与记录，`last_http_code=200`、`nv_err_exec=0`、`saved_hangs=0`、`saved_crashes=0`、`body_score_rpc_fail=0`。

Flowable 支线证据显示 20s 与 60s 最小 smoke 均有真实服务结果，其中 60s 结果为 `last_http_code=201`、`nv_err_exec=0`、`body_score_rpc_fail=0`。该结论只能支撑 Flowable 最小校准验证，不能扩展为完整 AFL++ mutation 主链。

## 4. 阶段性完成度

| 目标 | 阶段性判断 | 依据 |
| --- | --- | --- |
| 模糊测试方法 | 阶段性完成 | 已形成 AFL++ body harness、JSON mutator、规则有效性验证、评分判定和统计输出链路 |
| 高质量种子/用例生成 | 阶段性完成 | 仓库存在 O2OA 与 Flowable 种子集、规则集和数据集构造/筛选脚本；O2OA 主线已产生真实 smoke 结果 |
| 测评组件交付 | 阶段性完成 | 包含 target 配置、validity 规则、runner/adapter、profile、score service、结果报告和审查文档 |
| O2OA 主线 | 已通过真实服务 smoke | `out/cms_body_valid_compare_real/summary.csv` 与 `out/real_service_smoke_20260508/o2oa_real/summary.csv` 可作为主线证据 |
| Flowable 支线 | 已通过真实最小 smoke | `flowable_dur20/summary.csv` 与 `flowable_dur60/summary.csv` 可作为最小校准证据 |
| 总项目集成联调 | 可以进入 | 当前接口能力已能支撑 O2OA 主线与 Flowable 支线接入，但后续仍需平台化网关、更多接口和第三方环境部署 |

综合判断：任务4“模糊测试方法 + 高质量种子/用例生成 + 测评组件”可按阶段性完成处理；O2OA 主线真实服务 smoke 已补齐，Flowable 支线真实最小 smoke 已补齐，可以进入总项目集成联调。

后续建议聚焦三类工作：扩展更多 O2OA/电子政务接口，建设完整平台 API 网关服务，完成第三方测试环境部署与复现实验。

## 5. 禁止夸大表述

当前交付和汇报中应避免以下表述：

| 禁止表述 | 原因 | 稳妥表述 |
| --- | --- | --- |
| 已覆盖 O2OA 全业务流程 | 当前真实证据集中在 `cms_doc_list` 主线接口，其他 O2OA 配置接口未见本轮真实 smoke evidence | 已完成 O2OA CMS document filter/list 主线接口真实服务 smoke |
| Flowable 完整 AFL++ mutation 主链已完成 | Flowable 当前证据是 `python_static_loop / flowable_min_calibration` | Flowable process start 已完成真实服务最小校准 smoke |
| Flowable-GAN 已完成 | 当前 Flowable 正式 profile 是 Flowable-AE v2 + `flowable_rule_v1`，不是 Flowable-GAN | Flowable 支线采用 AE + `flowable_rule_v1` 二阶段验证 |
| GAN 替代 AE 成为默认主线 | O2OA 默认主线为 AE，GAN online 是二阶段增强或研究增强路线 | O2OA 默认 AE，GAN online 作为二阶段增强 |
| 完整拟态系统级动态异构冗余已完成 | 当前完成的是模糊测试有效性验证链路中的二阶段判定机制，不含执行体调度、自愈、重构 | 已完成模糊测试有效性验证链路中的二阶段判定机制 |
| 已有完整 HTTP/RPC 网关服务 | 当前是 runner/adapter 级 submit/query/stop/report_query 任务语义 | 已实现 runner/adapter 级平台任务语义 |
| adapter demo 是真实 fuzz 证据 | adapter demo 只验证任务语义和报告查询路径 | adapter demo 仅作为任务语义演示，不作为真实模糊测试效果证据 |

最终审计结论：当前仓库可支撑“以 O2OA CMS document filter/list 为主线、以 Flowable process start 为支线最小校准”的阶段性接口能力验收；可以进入总项目集成联调，但不能扩大为多平台全接口覆盖、Flowable 完整 AFL++ 主链、Flowable-GAN 或完整拟态系统级动态异构冗余完成。
# Alfresco 标准文档平台接口补充

## Alfresco 文档接口验证状态

Alfresco Community Edition 已在本地 Docker Compose 环境完成部署验证，root node API 返回 `Company Home`。

已完成手工验证：

- Alfresco 文档创建/保存成功；
- Alfresco 文档内容更新成功；
- Alfresco 文档元数据更新成功。

已完成接入验证：

- Alfresco metadata update 已接入并通过本地 smoke；
- 目标接口为 `PUT /alfresco/api/-default-/public/alfresco/versions/1/nodes/{NODE_ID}`；
- 该接口是 JSON body，最适配当前 body-only JSON fuzz 框架；
- 本地 smoke 结果为 `nv_total_valid_exec=4`、`nv_err_exec=0`、`nv_err_rate=0.000000`、`last_http_code=200`、`body_rule_pass=3`、`body_rule_reject=1`；
- `seed_bad_0.json` 是预设非法样本，在规则层被拒绝，不计为主链失败；
- 本轮未配置 `NV_BODY_SCORE_ENDPOINT`，因此 score 统计为 0。

审计边界：

- Alfresco 是标准文档平台证据，不是 O2OA 原生接口覆盖；
- Alfresco metadata update 验证的是文档元数据更新语义，不等同于完整文档内容 fuzz；
- 当前结论不能扩大为完整 AFL++ mutation-chain 或完整拟态系统级动态异构冗余完成。
