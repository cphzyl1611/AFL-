## 4. AFL++ 主链修改说明

当前三语义 online filter 交付复用真实 `./afl-fuzz` 执行短时 smoke、四模式消融和四模式短时稳定性实验。运行脚本使用 `afl-fuzz -n -m none -i <seed_dir> -o <out_dir> -- python3 <wrapper> @@` 形式，把 AFL++ 产生的变异输入传给 Python wrapper。

v0.6.1 不新增 AFL++ 核心逻辑，不修改 `src/` 或 `include/`。验收链路关注的是 AFL++ 代表性 mutation-chain 与本地 online filter wrapper 的工程集成，而不是新增 AFL++ 内核能力。

## 5. 三语义 mock target 与 wrapper 结构

| 语义 | seed 目录 | wrapper | mock target |
|---|---|---|---|
| content_update | `in/alfresco_afl_content_update_smoke/` | `targets/alfresco_content_update_online_filter_wrapper.py` | `targets/alfresco_content_update_mock.py` |
| metadata_update | `in/alfresco_afl_metadata_update_smoke/` | `targets/alfresco_metadata_update_online_filter_wrapper.py` | `targets/alfresco_metadata_update_mock.py` |
| multipart_upload | `in/alfresco_afl_multipart_upload_smoke/` | `targets/alfresco_multipart_upload_online_filter_wrapper.py` | `targets/alfresco_multipart_upload_mock.py` |

wrapper 的共同结构：

- 从 AFL++ `@@` 文件或 stdin 读取输入；
- 执行业务 rule filter；
- 按 `ONLINE_FILTER_MODE` 决定是否执行 AE v1 和 fAnoGAN candidate；
- 对过滤输入受控返回，不让 AFL++ 误判为 crash；
- 对通过过滤的输入调用本地 mock target；
- 将每次 online filter 判定写入 `filter_stats.jsonl`，再由 summarizer 汇总为正式 evidence。

## 6. AE v1 主判定机制调用链

AE v1 主判定代码位于：

- `model_stage/alfresco_ae_v1_scorer.py`
- `model_stage/alfresco_feature_extractor.py`
- `model_stage/models/alfresco_ae_v1_meta.json`

CodeGraph 显示 `AlfrescoAEV1Scorer` 提供三类评分方法：

- `score_text_content`：用于 content_update；
- `score_metadata_payload`：用于 metadata_update；
- `score_multipart_upload`：用于 multipart_upload。

调用链：

```text
online filter wrapper
-> AlfrescoAEV1Scorer
-> alfresco_feature_extractor
-> model_stage/models/alfresco_ae_v1_meta.json
-> score / decision / reason
-> wrapper final_decision
```

当前 recommendation 仍为 `keep_ae_v1_as_primary`。

## 7. fAnoGAN candidate 候选路径调用链

fAnoGAN candidate 相关代码位于：

- `model_stage/alfresco_fanogan_v1_candidate_scorer.py`
- `model_stage/alfresco_fanogan_v1_candidate.py`
- `model_stage/models/alfresco_fanogan_v1_candidate_meta.json`
- `model_stage/models/alfresco_fanogan_v1_candidate.pt`

调用链：

```text
online filter wrapper
-> AlfrescoFanoganV1CandidateScorer
-> feature extractor / candidate model metadata
-> candidate score / decision
-> wrapper final_decision
```

只有 `rule_fanogan` 和 `rule_ae_fanogan` 模式启用该路径。三语义 evidence 显示 fAnoGAN candidate 在线路径可运行且短时多轮无 scoring error，但推理成本高于 AE v1，未替代 AE v1。

## 9. evidence 生成与汇总链路

每个 smoke 目录保留三类小型正式 evidence：

- `summary.csv`
- `eval_report.json`
- `fuzzer_stats`

四模式消融汇总输出：

- `ablation_summary.csv`
- `ablation_details.csv`
- `ablation_report.json`

四模式短时稳定性汇总输出：

- `stability_summary.csv`
- `stability_details.csv`
- `stability_report.json`

总体验收 evidence：

- `out/three_semantics_online_filter_delivery_matrix.csv`
- `out/three_semantics_online_filter_delivery_report.json`

`.gitignore` 显式排除 AFL runtime internals，包括 `queue/`、`crashes/`、`hangs/`、`fastresume*`、`mock_stats*`、`filter_stats*`、`plot_data`、`cmdline`、`fuzzer_setup`、`target_hash`。正式提交只保留小型 summary/report/fuzzer_stats 类 evidence。

## 10. API / MCP prototype 集成说明

轻量 API 位于 `integration/api_server.py`，提供 localhost-only 能力查询、报告索引、任务语义封装和 `POST /score/alfresco_ae_v1` 本地 scoring adapter。该 adapter 复用 `AlfrescoAEV1Scorer`，不访问 Alfresco 服务。

MCP-like adapter 位于 `integration/mcp_adapter.py`，只暴露白名单工具：

- `get_capabilities`
- `score_alfresco_ae_v1_sample`
- `list_reports`
- `query_evidence`

该 adapter 不依赖外部 MCP SDK，不执行任意 shell，不读取任意路径，不访问真实 Alfresco 服务。

## 11. 测试与交付校验链路

交付校验入口：

- `scripts/validate_project_configs.py`
- `python3 -m unittest discover -s tests`
- `scripts/delivery_preflight_check.py`

测试覆盖：

- AE v1 scorer 和模型元数据；
- fAnoGAN candidate scorer 和 holdout/diagnosis evidence；
- 三语义 smoke、ablation、stability 脚本存在性和 summary header；
- API server 和 MCP adapter prototype；
- 三语义 delivery matrix、v0.6.1 delivery docs。

preflight 会组合关键文件存在性、Python 编译、配置校验、unittest、API smoke、敏感信息扫描和 overclaim 口径扫描。
