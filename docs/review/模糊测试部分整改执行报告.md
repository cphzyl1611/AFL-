## 阻塞项说明

### RISK-01：O2OA 默认 AE 模型 source-of-truth 不明

阻塞原因：

- `model_stage/models/sefanogan_ae_model.pt` 与 `model_stage/models/flowable_ae_v3_model.pt` 哈希相同，不能证明它是 O2OA AE@1.0。
- `model_stage/models/sefanogan_ae_meta.json` 的统计值与 Flowable v3 meta 相同，不符合终审报告中的 O2OA 默认基线口径。
- `docs/final_results/batch_compare_runs/baseline_156_run*/sefanogan_ae_model.pt` 中存在多个候选权重，但没有一个文件被当前仓库明确标注为“最终 O2OA 默认 AE@1.0 权重”。

需要人工补充：

1. 指定最终 O2OA AE@1.0 的 `.pt` 和 `.json` meta source-of-truth。
2. 提供期望哈希或明确采用哪一次 baseline_156 run 的权重。
3. 确认后再替换 `model_stage/models/sefanogan_ae_model.pt`、`model_stage/models/sefanogan_ae_meta.json`，并补齐交付目录。

为什么不能安全自动整改：

- 自动选择 run1/run2/run3 任意一个权重都是猜测。
- 用 Flowable v3 覆盖 O2OA 默认模型会继续扩大错误。
- 本次约束明确禁止凭猜测覆盖模型文件。

### RISK-02：交付目录缺 O2OA `.pt` 权重

阻塞原因：

- 交付目录 `docs/final_delivery/fuzz_component_release/` 没有 O2OA AE/GAN `.pt` 权重。
- GAN source-of-truth 可以从 `model_stage/models/sefanogan_gan_model.pt` 与 t17_ab9010 run3 结果中确认，但 O2OA AE source-of-truth 未确认。
- 只补 GAN、不补 AE 会让“交付目录完整性”仍然不成立，并可能造成用户误判为已全部修复。

需要人工补充：

1. 确认 O2OA AE 最终权重和 meta。
2. 决定交付目录是否应包含 `.pt` 文件，还是在 README 中指向外部模型包。
3. 若要求交付目录自包含，则人工确认后补齐 `sefanogan_ae_model.pt`、`sefanogan_ae_meta.json`、`sefanogan_gan_model.pt`、`sefanogan_gan_meta.json`。

为什么不能安全自动整改：

- `.pt` 权重属于模型交付物，不能伪造，也不能在 source-of-truth 不完整时自动拷贝。
- 当前 O2OA AE 权重不明，无法保证交付目录补齐后的可复现性。
