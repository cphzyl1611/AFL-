# 指标字段映射说明

## 1. 说明目的

本说明用于统一河南重大专项模糊测试模块最终验收中的指标解释。仓库中同时保留了 AFL++ 改造早期、AE 评分服务联调、online filter prototype、三语义 delivery matrix 等不同阶段的结果文件，因此部分历史字段与当前三语义 online filter 主统计字段并存。

当前最终验收不应只读取单一字段，而应结合 `summary.csv`、`fuzzer_stats`、`eval_report.json` 与 `out/three_semantics_online_filter_delivery_matrix.csv` 共同解释。

## 2. 历史字段与当前字段的关系

`valid_passed` / `valid_skipped` 属于历史或兼容性口径，主要用于表达“输入是否通过有效性判定”以及“是否被过滤跳过”。在当前三语义 online filter 交付证据中，主口径已细化为：

- `body_rule_pass` / `body_rule_reject`：规则层过滤结果；
- `body_score_pass` / `body_score_reject`：二阶段 scorer 判定结果；
- `body_score_rpc_ok` / `body_score_rpc_fail`：scorer 调用是否成功；
- `nv_total_valid_exec` / `nv_err_exec`：AFL++ 运行侧有效执行与错误统计；
- `sent_to_target` / `filtered_by_rule` / `filtered_by_ae` / `filtered_by_fanogan`：online filter wrapper 的路径分流统计。

因此，`valid_passed` / `valid_skipped` 不应单独作为最终验收唯一指标。若需要兼容解释，应把它们映射为当前主口径中的规则判定、scorer 判定与 target 分流统计的组合。

## 3. 主统计字段说明

| 字段 | 所在文件 | 含义 | 当前验收解释 |
| -- | ---- | -- | ------ |
| `nv_total_valid_exec` | `fuzzer_stats`, `summary.csv`, `eval_report.json` | AFL++ 或汇总脚本记录的有效执行计数 | 用于衡量本轮短时运行实际完成的有效样本执行规模 |
| `nv_err_exec` | `fuzzer_stats`, `summary.csv`, `eval_report.json` | 有效性链路或执行链路中的错误执行计数 | 当前三语义稳定性验收要求该字段为 0 |
| `nv_err_rate` | `summary.csv` | `nv_err_exec / nv_total_valid_exec` | 用于比较不同模式或多轮运行的错误率 |
| `body_rule_pass` | `summary.csv`, wrapper 统计 | 通过规则层检查的输入数 | 表示输入在业务语义规则层未被过滤 |
| `body_rule_reject` | `summary.csv`, wrapper 统计 | 被规则层拒绝的输入数 | 表示输入未进入后续 scorer 或 target 执行 |
| `body_score_pass` | `summary.csv` | 通过 AE v1 或 fAnoGAN candidate scorer 的输入数 | 表示二阶段判定允许继续进入 target 的样本规模 |
| `body_score_reject` | `summary.csv` | 被 scorer 拒绝的输入数 | 表示输入被二阶段判定过滤 |
| `body_score_rpc_ok` | `summary.csv`, `eval_report.json` | scorer 调用成功次数 | 用于确认 AE v1 或 fAnoGAN candidate 在线路径可运行 |
| `body_score_rpc_fail` | `summary.csv`, `eval_report.json` | scorer 调用失败次数 | 当前三语义 online filter 验收要求该字段为 0 |
| `saved_crashes` | `fuzzer_stats`, `summary.csv`, stability/ablation report | AFL++ 保存的 crash 数 | 当前短时 smoke 与稳定性实验中应为 0 |
| `saved_hangs` | `fuzzer_stats`, `summary.csv`, stability/ablation report | AFL++ 保存的 hang 数 | 当前短时 smoke 与稳定性实验中应为 0 |
| `sent_to_target` | online filter `summary.csv` | 通过 rule/scorer 后实际送入本地 mock target 的输入数 | 用于说明 online filter 前置过滤后的 target 执行规模 |
| `filtered_by_rule` | online filter `summary.csv` | 被规则层过滤的输入数 | 用于解释 mock 业务语义规则的过滤贡献 |
| `filtered_by_ae` | online filter `summary.csv` | 被 AE v1 过滤的输入数 | 用于解释当前主二阶段判定机制的过滤贡献 |
| `filtered_by_fanogan` | online filter `summary.csv` | 被 fAnoGAN candidate 过滤的输入数 | 仅表示候选路径运行结果，不表示替代 AE v1 |

## 4. AE v1 与 fAnoGAN candidate 字段说明

三语义 online filter 支持 `rule_only`、`rule_ae`、`rule_fanogan`、`rule_ae_fanogan` 四种模式：

- `rule_ae` 是默认模式，表示规则层过滤后接入 AE v1 scorer；
- `rule_fanogan` 与 `rule_ae_fanogan` 用于验证 fAnoGAN candidate 在线路径是否可运行；
- `FANOGAN_ENABLED=1` 仅说明 fAnoGAN candidate scorer 被启用，不表示其成为主机制；
- `ae_primary_recommendation=keep_ae_v1_as_primary` 是当前最终验收的推荐结论；
- `body_score_rpc_fail=0` 说明 scorer 调用稳定，不等同于证明 fAnoGAN candidate 效果优于 AE v1。

## 5. 最终验收推荐口径

最终验收建议以三语义 delivery matrix、各场景 `summary.csv`、`fuzzer_stats` 与 `eval_report.json` 共同解释结果。其中，AE v1 作为当前主二阶段判定机制，fAnoGAN candidate 仅作为可运行候选路径，不应解释为已经替代 AE v1。

当前成果属于三语义 online filter 阶段性交付闭环，不等同于完整 SE-fAnoGAN-ES、完整 GAN/fAnoGAN、真实 Alfresco 服务完整覆盖、O2OA 电子公文接口全量 online fuzz、长时间稳定性实验或系统级 DHR。
