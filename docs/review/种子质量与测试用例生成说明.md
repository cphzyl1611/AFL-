# 种子质量与测试用例生成说明

## 1. 种子设计目标

当前种子设计目标包括：

- 覆盖正常样本；
- 覆盖边界样本；
- 覆盖预设非法样本；
- 覆盖文档类业务语义字段；
- 支持结构保持型 JSON 变异。

## 2. 种子来源和目录

当前种子来源包括：

- O2OA seeds：用于 O2OA CMS document filter/list 等 HTTP/REST JSON 场景；
- Flowable process start seeds：用于 Flowable process start 最小校准；
- Flowable `documentProcess` seeds：用于电子公文替代场景的创建/保存和内容更新；
- Alfresco metadata update seeds：用于文档标题、描述等元数据更新 JSON body 场景。

典型目录包括：

- `in/o2oa_body`
- `in/o2oa_body_cms_score`
- `in/o2oa_body_model_compare`
- `in/flowable_process_start`
- `in/flowable_process_start_dataset`
- `in/flowable_doc_create_dataset`
- `in/flowable_doc_update_dataset`
- `in/alfresco_metadata_update_dataset`

## 3. 种子质量统计

本轮已生成种子质量统计 evidence：

- `docs/review/evidence/seed_quality_summary.json`
- `docs/review/evidence/seed_quality_summary.csv`

统计内容包括：

- seed 数量；
- JSON seed 数量；
- 有效/无效 JSON 数量；
- 正常、边界、预设非法样本数量；
- 文件大小统计；
- 顶层字段覆盖；
- 嵌套字段路径覆盖；
- 文档业务字段覆盖；
- 是否包含预设非法样本。

脚本入口：

```text
scripts/analyze_seed_quality.py
```

## 4. 生成方法

当前采用的生成方法包括：

- 人工构造合法业务 seed；
- 边界样本；
- 预设非法样本；
- JSON 结构保持型变异；
- `validity` rules 过滤。

其中 `seed_bad_0.json` 类样本用于验证规则层或目标系统对非法结构的拒绝行为，不应解释为主链失败。

## 5. 局限性

- 当前不是完全自动化语义种子生成；
- 当前已完成 NV_MAB 工程闭环，支持 `field_value`、`boundary`、`structure` 三类 JSON 变异 arm，支持 `mutation_scope` 限制，并通过本地最小 smoke 验证；但不等同于完整理论级 NC_MAB、长时间稳定性实验或完整消融验证；
- 当前以工程启发式和结构保持型 JSON 变异为主。
