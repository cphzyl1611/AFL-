# v0.6.1验收答辩口径说明

## 1. 当前项目做到什么程度？

当前模糊测试模块已经形成阶段性交付闭环：以 Alfresco 文档类业务语义为主验证对象，完成 content_update/text/plain、metadata_update/application/json、multipart_upload/multipart-form-data 三类本地 mock 语义的 online filter smoke、四模式消融和四模式 3 轮短时稳定性实验。

同时，项目保留 O2OA 历史 smoke、Flowable 替代建模资料、AE v1 主判定机制、fAnoGAN candidate 候选路径、NV_MAB 工程闭环、轻量 API 和 MCP adapter prototype 等交付材料。

## 2. 为什么当前以 Alfresco 为主验证平台？

Alfresco 提供更清晰的文档平台接口语义，便于覆盖文档内容更新、元数据更新和 multipart 文件上传三类典型文档业务输入。当前三语义 online filter 矩阵以 Alfresco 语义为主，可以更直接地呈现模糊测试、规则过滤、AE v1 scoring 和候选 fAnoGAN 路径的工程闭环。

## 3. O2OA 的历史资料如何处理？

O2OA 仍作为原项目指定场景和历史 smoke evidence 保留，不删除、不否定。当前口径是：O2OA 历史资料用于说明早期 HTTP/REST JSON 主链和需求来源；后续主验证平台调整为 Alfresco，Flowable 保留为流程型电子公文替代建模资料。

## 4. 为什么当前使用本地 mock target？

本地 mock target 用于在授权、可控、可复现环境中验证 AFL++ mutation-chain、online filter、AE v1 scorer 和 fAnoGAN candidate 在线路径。它避免依赖真实服务账号、网络状态、权限和外部服务稳定性，使短时 smoke、消融和稳定性实验可以稳定复现。

## 5. 当前是否是真实 Alfresco 服务覆盖？

不是。当前三语义 online filter smoke、四模式消融和四模式短时稳定性实验均使用本地 mock target，不代表真实 Alfresco 服务覆盖。仓库中保留了部分 Alfresco 手工真实服务 min_calibration evidence，但不能把这些 evidence 扩大解释为完整真实 Alfresco 服务覆盖。

## 6. 当前是否是完整 SE-fAnoGAN-ES？

不是。当前是 SE-fAnoGAN-ES-style online filter prototype：规则过滤、AE v1 主评分和可选 fAnoGAN candidate 被接入代表性 AFL++ 链路，但没有宣称完整 SE-fAnoGAN-ES 的全部理论、训练、系统集成和生产级闭环。

## 7. 当前是否是完整 GAN/fAnoGAN？

不是。当前 fAnoGAN candidate 是候选评分路径，包含 fallback 与 torch fAnoGAN-style candidate 的工程化对比、阈值校准、holdout 验证和 online path smoke。它不等同于完整 GAN/fAnoGAN。

## 8. 为什么 fAnoGAN candidate 没有替代 AE v1？

证据显示 fAnoGAN candidate 在线路径可运行，并在三语义短时稳定性 evidence 中未出现 scoring error。但它的推理成本明显高于 AE v1，且没有形成优于 AE v1 的稳定收益证据。因此当前 recommendation 仍为 `keep_ae_v1_as_primary`，fAnoGAN candidate 未替代 AE v1。

## 9. 当前短时稳定性实验能说明什么，不能说明什么？

能说明：

- 三类本地 mock 文档语义均完成四模式 3 轮短时 AFL++ 运行；
- 纳入矩阵的 stability summary 中 `saved_crashes_total=0`、`saved_hangs_total=0`、`total_err_exec=0`、`scoring_error_total=0`；
- fAnoGAN candidate 在线路径在短时多轮中可运行且无 scoring error。

不能说明：

- 不能说明长时间稳定性实验已经完成；
- 不能说明真实 Alfresco 服务已完整覆盖；
- 不能说明所有场景完整 AFL++ mutation-chain 均已覆盖；
- 不能说明 fAnoGAN candidate 已经替代 AE v1。

## 10. 当前是否完成系统级 DHR？

没有。当前只完成测评链路级二阶段异构判定增强和相关 evidence，不能宣称系统级动态异构冗余 DHR 完整完成。系统级 DHR 还需要多执行体调度、输出裁决、动态重构、自愈恢复和总系统联调证据。

## 11. 如果验收问“还有哪些未完成”，应该如何回答？

建议回答：

- 真实 Alfresco 服务覆盖还需要在授权环境中扩展；
- 长时间稳定性实验尚未完成；
- fAnoGAN candidate 仍是候选路径，未替代 AE v1；
- 当前 MCP adapter 是 prototype，不是完整 MCP Server；
- 系统级 DHR 未完成，当前只覆盖模糊测试测评链路中的判定增强；
- 所有场景完整 AFL++ mutation-chain 覆盖尚未完成。

## 12. 当前最适合宣称的交付结论是什么？

当前最适合宣称：

河南重大专项模糊测试模块已经完成以 Alfresco 文档类业务语义为主的三语义 online filter 阶段性交付闭环。content_update、metadata_update、multipart_upload 三类本地 mock 文档语义均完成 AFL++ online filter smoke、四模式消融和四模式短时稳定性实验；AE v1 仍为主二阶段判定机制；fAnoGAN candidate 作为可运行候选路径保留但未替代 AE v1；正式 evidence 已按 summary/report/fuzzer_stats 等小型文件归档，并排除 AFL runtime internals。

该结论不等同于完整 SE-fAnoGAN-ES、完整 GAN/fAnoGAN、真实 Alfresco 服务覆盖、长时间稳定性实验、所有场景完整 AFL++ mutation-chain 或系统级 DHR 完整完成。
