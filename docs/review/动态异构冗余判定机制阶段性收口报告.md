# 动态异构冗余判定机制阶段性收口报告

## 1. 收口范围

本报告收口的是“模糊测试有效性验证链路中的二阶段异构判定增强机制”。

该机制不是完整拟态系统级动态异构冗余，不涉及多执行体调度、输出裁决、动态重构、自愈恢复等系统级能力。

当前机制服务于测试样本有效性判定、输入质量控制和测试结果解释，用于增强模糊测试模块在多平台、多规则、多模型条件下的样本筛选与结果说明能力。

## 2. 机制设计

当前测评链路版 DHR 的基本结构包括一级判定和二阶段判定。

一级判定：

- 规则过滤；
- AE 模型评分。

二阶段判定：

- O2OA GAN online；
- Flowable rule / `flowable_rule_v1`；
- 平台规则或 fallback 判定。

动态性体现：

- 根据阈值、规则结果或灰区样本进入不同判定路径；
- 判定结果输出 `pass` / `reject` / `fallback` / `decision_source`；
- 统计 `body_rule_pass` / `body_rule_reject`、`body_score_pass` / `body_score_reject`、`body_score_rpc_ok` / `body_score_rpc_fail` 等字段。

## 3. O2OA 主线证据

O2OA 是当前动态异构判定机制的主线证据。

O2OA 使用 AE 默认评分链路，并使用 GAN online 作为二阶段增强。O2OA 真实 smoke 已通过，在 `rule_score` 模式下无 crash、无 hang、无评分 RPC 失败。

O2OA 可支撑“AE + GAN online 二阶段判定链路已阶段性跑通”这一结论。

边界说明：

- 不能写成 O2OA 原生电子公文创建/保存、内容更新接口已完成；
- O2OA CMS document filter/list 是 O2OA 基础 HTTP/REST JSON 主链证据。

## 4. Flowable 支线证据

Flowable process start 用作第二平台支线。

Flowable 使用 Flowable-AE v2 + `flowable_rule_v1`，Flowable process start 真实最小 smoke 已通过。

Flowable `documentProcess` 用于电子公文替代场景：

- 创建/保存映射为流程实例启动；
- 内容更新映射为流程变量更新。

Flowable 支线验证的是流程型 HTTP/REST JSON 接口适配能力和平台规则二阶段判定能力。

边界说明：

- Flowable 不是 O2OA 原生接口覆盖；
- Flowable 不是完整 AFL++ mutation-chain；
- Flowable-GAN 未完成，不能宣称。

## 5. Alfresco 的位置

Alfresco 是标准文档平台接口能力扩展证据。

Alfresco metadata update 已接入并通过本地 smoke，证明项目可测文档类业务语义接口。

但 Alfresco 本轮未配置 `NV_BODY_SCORE_ENDPOINT`，Alfresco profile 中 `enable_second_stage=false`。因此 Alfresco 不作为动态异构冗余判定机制的核心证据，只作为接口能力扩展证据。

## 6. 当前完成度判断

已完成：

- 规则过滤；
- AE 一阶段判定；
- O2OA GAN online 二阶段增强；
- Flowable rule 二阶段判定；
- `summary.csv` / `fuzzer_stats` / `eval_report.json` 等统计链路；
- 多平台接口能力验证；
- 文档类业务接口能力收口。

基本完成：

- 模糊测试有效性验证链路中的二阶段异构判定增强机制。

未完成：

- 完整拟态系统级动态异构冗余；
- 多异构执行体部署；
- 输入复制分发；
- 多执行体输出裁决；
- 异常执行体剔除；
- 动态重构；
- 自愈恢复；
- 长时间系统级稳定性验证。

## 7. 可以宣称什么

可以宣称：

- 当前已完成测评链路版动态异构判定机制的阶段性实现；
- O2OA 主线完成 AE + GAN online 二阶段验证；
- Flowable 支线完成 AE v2 + `flowable_rule_v1` 判定验证；
- 该机制提升了测试样本有效性判断能力和测试结果解释能力；
- 可以进入总项目集成联调。

## 8. 不能宣称什么

不能宣称：

- 完整动态异构冗余已经完成；
- 完整拟态系统级执行体调度、自愈、重构完成；
- Flowable-GAN 完成；
- Alfresco metadata update 证明动态异构冗余完成；
- Flowable 完整 AFL++ mutation-chain 完成；
- O2OA 原生电子公文写入接口全覆盖。

## 9. 后续建议

当前阶段不建议继续扩展完整系统级 DHR。

建议保留现有测评链路版 DHR 作为模糊测试模块增强机制。

后续如总项目提供拟态执行体环境，再开展系统级 DHR 对接。

当前工作重点应转为交付文档、README、接口能力报告和总项目集成联调。

## 10. 最终结论

当前已经基本完成“模糊测试有效性验证链路中的二阶段异构判定增强机制”，可作为测评链路版动态异构冗余阶段性成果；但不等同于完整拟态系统级动态异构冗余。建议停止继续扩大 DHR 功能面，转入阶段性收口和总项目集成联调。
