# 内生安全性能评分模型实现说明

## 1. 目的

本文档说明当前工程化评分模型如何从已有 `summary.csv`、`fuzzer_stats`、`eval_report.json` 等指标中计算 0-100 分。

该评分用于阶段性验收、横向比较和结果解释，是内生安全性能评估模型的工程化实现雏形，不是最终权威安全等级评估体系。

## 2. 指标来源

当前评分优先读取 `summary.csv` 中的统一字段。

可关联参考的结果文件包括：

- `summary.csv`
- `fuzzer_stats`
- `eval_report.json`
- `details.csv`，可选，用于逐 seed 解释

本轮已生成的工程化评分结果：

- `docs/review/evidence/security_score_summary.json`
- `docs/review/evidence/security_score_summary.csv`

## 3. 评分维度

当前评分维度包括：

- `error_score`：错误率得分；
- `validity_score`：规则有效输入比例得分；
- `score_rpc_health`：评分 RPC 健康度；
- `coverage_proxy_score`：覆盖代理得分；
- `stability_score`：稳定性得分；
- `final_score_0_100`：可用指标加权后的综合工程评分。

## 4. 公式

`error_score`：

```text
error_score = 100 * (1 - min(max(nv_err_rate, 0), 1))
```

`nv_err_rate` 越低越好。

`validity_score`：

```text
validity_score = 100 * body_rule_pass / (body_rule_pass + body_rule_reject)
```

如果分母为 0，则记为 unavailable，不参与加权。

`score_rpc_health`：

```text
score_rpc_health = 100 * body_score_rpc_ok / (body_score_rpc_ok + body_score_rpc_fail)
```

如果 `body_score_rpc_ok=0` 且 `body_score_rpc_fail=0`，说明本轮可能未配置 score endpoint，该项记为 unavailable，不参与加权。

`coverage_proxy_score`：

```text
coverage_proxy_score = min(last_ncov_total / 100, 1.0) * 100
```

如果 `last_ncov_total=0`，该项记为 unavailable，不参与加权。该指标是覆盖代理分，不是完整代码覆盖率。

`stability_score`：

```text
stability_score = 100                         # saved_hangs=0 且 saved_crashes=0
stability_score = max(0, 100 - 20 * saved_hangs - 30 * saved_crashes)
```

`final_score_0_100`：

默认权重：

```text
error_score: 0.35
validity_score: 0.20
score_rpc_health: 0.15
coverage_proxy_score: 0.15
stability_score: 0.15
```

如果某项为 unavailable，则该项不参与加权，其权重在可用项中重新归一化。

## 5. 局限性

- 当前是工程化评分雏形；
- `coverage_proxy_score` 不是完整代码覆盖率；
- 当前模型未完全替代项目最终综合评价体系；
- 该评分可用于阶段性验收和横向比较，不宜过度解释为最终安全等级。
