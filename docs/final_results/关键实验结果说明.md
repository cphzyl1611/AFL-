## 3. 敏感接口说明

### 3.1 接口

* `calendar_filter`

### 3.2 当前定位

`calendar_filter` 不纳入当前阶段正式主实验基线接口。

### 3.3 原因

在通用多接口主实验中，`calendar_filter` 表现出更高的敏感性：

* baseline 下已出现错误执行与 hang
* rule_only 下错误率显著上升
* 对 body 内容更敏感
* 当前一级规则还不足以充分约束其业务语义

### 3.4 当前建议

将 `calendar_filter` 作为：

* 规则增强实验对象
* 二级 score 增强实验对象
* 敏感接口专项分析对象

而不是当前正式主实验基线接口。

## 7. 当前阶段正式结论

结合上述结果，当前阶段可以形成以下正式结论：

### 7.1 主线已完成

已经完成面向真实 O2OA 平台的 body-only 模糊测试主链路构建，并可稳定运行通用主实验。

### 7.2 一级规则已形成正式方案

一级规则验证可以在不显著影响执行效率的前提下过滤大量无效 JSON 输入，并且不会被误计为平台错误执行，因此已可作为当前阶段正式有效性验证方案。

### 7.3 框架已具备平台无关雏形

通过 target 配置、validity 规则、通用 body validator、通用执行器和通用主实验脚本的分层设计，当前系统已具备迁移到其他 JSON API 平台的基本能力。

### 7.4 二级 score 已作为增强模块接入

二级 score 已成功接入并具备初步能力，但其自动 fuzz 条件下的稳定增益仍需进一步增强，因此当前更适合作为增强模块，而非正式主实验唯一支撑。
