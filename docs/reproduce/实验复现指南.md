# 实验复现指南

## 1. 适用范围与边界

本指南用于复现当前阶段性验证结果，面向第一次接触本项目的复现实验人员。

需要明确以下边界：

- Flowable 是电子公文替代场景，不是 O2OA 原生接口；
- Alfresco 是标准文档平台验证，不是 O2OA 原生接口；
- O2OA 真实 smoke 需要当前会话 token；
- 当前复现包含 `python_static_loop` / `min_calibration`、AFL++/HTTP harness smoke、NV_MAB 本地 smoke/stability/ablation；
- 当前结果不代表完整拟态系统级动态异构冗余。

## 2. 推荐复现顺序

建议按以下顺序复现：

1. NV_MAB 本地验证；
2. Flowable `documentProcess`；
3. Alfresco metadata update；
4. O2OA 真实 smoke，可选。

原因：

- NV_MAB 不依赖外部服务；
- Flowable 相对稳定；
- Alfresco 最贴近文档类业务语义；
- O2OA 依赖 token、权限和业务环境。

## 3. 环境要求

建议环境：

- WSL2 或 Linux；
- Docker；
- Docker Compose；
- Python 3；
- Python 虚拟环境；
- AFL++ 编译环境；
- 本地授权测试服务。

## 4. 仓库准备

进入仓库目录：

```bash
cd ~/AFLplusplus
```

如果路径不同，请替换为自己的实际仓库路径。

两项均通过后再继续复现。

## 7. Flowable documentProcess 复现

### 7.1 确认 Flowable 服务

查看容器：

```bash
docker ps
```

验证 Flowable REST：

```bash
curl --noproxy '*' -i -m 8 \
  -u rest-admin:test \
  http://127.0.0.1:8080/flowable-rest/service/management/engine
```

HTTP 200 表示 Flowable REST 可用。

### 7.2 部署 documentProcess

```bash
curl --noproxy '*' -i -m 20 \
  -u rest-admin:test \
  -F "file=@flowable_models/document_process.bpmn20.xml" \
  http://127.0.0.1:8080/flowable-rest/service/repository/deployments
```

HTTP 201 表示部署成功。

### 7.3 启动 Flowable score service

在一个独立终端启动 Flowable-AE v2 score service：

```bash
SEFANOGAN_MODE=ae \
SEFANOGAN_MODEL_PATH=model_stage/models/flowable_ae_v2_model.pt \
SEFANOGAN_AE_META_PATH=model_stage/models/flowable_ae_v2_meta.json \
NV_VALID_SOCK=/tmp/nv_valid_flowable.sock \
.venv/bin/python model_stage/nv_valid_server_real.py
```

该终端保持不关闭，后续脚本通过 `/tmp/nv_valid_flowable.sock` 调用评分服务。

### 7.4 运行创建/保存替代场景

```bash
OUT_DIR="out/flowable_doc_create_manual_$(date +%Y%m%d_%H%M%S)"
PYTHONPATH=. \
FLOWABLE_BASE=http://127.0.0.1:8080 \
FLOWABLE_USER=rest-admin \
FLOWABLE_PASS=test \
NV_BODY_SCORE_ENDPOINT=unix:///tmp/nv_valid_flowable.sock \
NV_DECISION_PROFILE_PATH=integration/platform_profiles/flowable_document_process.json \
IN_DIR=in/flowable_doc_create_dataset \
OUT_DIR="$OUT_DIR" \
python3 scripts/run_flowable_doc_create_compare.py
cat "$OUT_DIR/summary.csv"
```

期望结果：

- `last_http_code=201`
- `nv_err_exec=0`
- `body_score_rpc_fail=0`
- `execution_scope=flowable_document_create_min_calibration`

## 8. Alfresco metadata update 复现

### 8.1 启动 Alfresco

Alfresco 部署目录示例：

```bash
cd ~/alfresco-lab/acs-deployment/docker-compose
docker compose -f community-compose.yaml up -d
docker compose -f community-compose.yaml ps
```

如果 Alfresco 已启动，只需确认容器 healthy 或接口可访问。

### 8.2 验证 root node

```bash
curl -u admin:admin \
  "http://127.0.0.1:8080/alfresco/api/-default-/public/alfresco/versions/1/nodes/-root-" \
  | python3 -m json.tool
```

返回 `Company Home` 表示 Alfresco REST API 可用。

### 8.3 运行 metadata update smoke

```bash
cd ~/AFLplusplus
OUT_DIR="out/alfresco_metadata_update_manual_$(date +%Y%m%d_%H%M%S)"
PYTHONPATH=. \
ALFRESCO_BASE=http://127.0.0.1:8080 \
ALFRESCO_USER=admin \
ALFRESCO_PASS=admin \
IN_DIR=in/alfresco_metadata_update_dataset \
OUT_DIR="$OUT_DIR" \
NV_DECISION_PROFILE_PATH=integration/platform_profiles/alfresco_metadata_update.json \
python3 scripts/run_alfresco_metadata_update_compare.py
cat "$OUT_DIR/summary.csv"
cat "$OUT_DIR/details.csv"
```

说明：

- metadata update 是 JSON body；
- 当前未必配置 `NV_BODY_SCORE_ENDPOINT`，因此 score 统计可以为 0；
- Alfresco 不是 O2OA 原生接口覆盖。

## 11. 常见问题

### Docker credential helper 报 `docker-credential-desktop.exe not found`

通常是 WSL2 里 Docker credential helper 配置指向 Windows Desktop。可检查 Docker 配置，或改用当前 Linux 环境可用的 credential helper。

### 8080 端口冲突

Flowable 和 Alfresco 示例都使用 `127.0.0.1:8080`。同一时间只启动一个，或调整 Docker Compose 端口映射。

### Flowable 401

检查账号密码是否为 `rest-admin:test`，并确认访问的是 `/flowable-rest/service/...`。

### Flowable documentProcess 未部署

重新执行部署命令，并通过 `process-definitions?key=documentProcess` 确认可查询到 `documentProcess`。

### score socket `ConnectionRefused`

检查 score service 终端是否仍在运行，`NV_VALID_SOCK` 与 `NV_BODY_SCORE_ENDPOINT` 是否指向同一个 socket。

### Python 缺 `numpy` / `torch`

修复虚拟环境或安装项目依赖后重试。使用 `.venv/bin/python` 时尤其要确认依赖安装在同一个虚拟环境中。

### Alfresco root API 访问失败

检查 Alfresco 容器健康状态、8080 端口映射、账号密码和服务启动时间。Alfresco 初次启动可能需要等待。

### O2OA `NV_TOKEN is required`

设置 `NV_TOKEN` 环境变量后重试，不要把真实 token 写入任何文件。

### O2OA 401 / `ExceptionUnauthorized`

优先检查 token 是否过期，其次检查权限和 O2OA 服务状态。

### `seed_bad_0.json` 为什么会被拒绝

`seed_bad_0.json` 是预设非法样本，用于验证规则层或目标系统对非法结构的拒绝行为，不应解释为主链失败。

### NV_MAB 单 arm 不符合预期

检查：

- C 侧是否设置 `NV_CUR_ARM`；
- Python mutator 是否写回 `NV_JSON_ARM_USED`；
- `mutation_scope` 是否只启用了目标 arm；
- `fuzzer_stats` 中 `nv_mab_arm0_pulls`、`nv_mab_arm1_pulls`、`nv_mab_arm2_pulls` 是否符合预期。
