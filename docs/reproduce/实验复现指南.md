# 实验复现指南

## 1. 适用范围与边界

本指南用于复现当前阶段性验证结果，面向第一次接触本项目的复现实验人员。

当前冻结交付版本说明见：

- `docs/review/v0.3.5最终工程交付状态冻结说明.md`

需要明确以下边界：

- Flowable 是电子公文替代场景，不是 O2OA 原生接口；
- Alfresco 是标准文档平台验证，不是 O2OA 原生接口；
- O2OA 真实 smoke 需要当前会话 token；
- 当前复现包含 `python_static_loop` / `min_calibration`、代表性 AFL++ mutation-chain smoke、AFL++/HTTP harness smoke、NV_MAB 本地 smoke/stability/ablation；
- 当前结果不代表完整拟态系统级动态异构冗余。

## 2. 推荐复现顺序

建议按以下顺序复现：

1. NV_MAB 本地验证；
2. 代表性 Alfresco content_update AFL++ mutation-chain smoke；
3. Alfresco metadata update / content update / multipart upload；
4. Alfresco AE v1 本地 score compare；
5. Flowable `documentProcess`；
6. O2OA 真实 smoke，可选。

原因：

- NV_MAB 不依赖外部服务；
- Alfresco 是后续主验证平台，最贴近标准文档类业务语义；
- Alfresco AE v1 不依赖 Alfresco 在线服务，可本地复现二阶段有效性判定；
- Flowable 相对稳定，保留为电子公文流程替代场景；
- O2OA 依赖 token、权限和业务环境。

## 3. 环境要求

建议环境：

- WSL2 或 Linux；
- Docker；
- Docker Compose；
- Python 3；
- Python 虚拟环境；
- AFL++ 编译环境；
- 本地授权测试服务。

## 15. 常见问题

### Docker credential helper 报 `docker-credential-desktop.exe not found`

通常是 WSL2 里 Docker credential helper 配置指向 Windows Desktop。可检查 Docker 配置，或改用当前 Linux 环境可用的 credential helper。

### 8080 端口冲突

Flowable 和 Alfresco 示例都使用 `127.0.0.1:8080`。同一时间只启动一个，或调整 Docker Compose 端口映射。

### Flowable 401

检查账号密码是否为 `rest-admin:test`，并确认访问的是 `/flowable-rest/service/...`。

### Flowable documentProcess 未部署

重新执行部署命令，并通过 `process-definitions?key=documentProcess` 确认可查询到 `documentProcess`。

### score socket `ConnectionRefused`

检查 score service 终端是否仍在运行，`NV_VALID_SOCK` 与 `NV_BODY_SCORE_ENDPOINT` 是否指向同一个 socket。

### Python 缺 `numpy` / `torch`

修复虚拟环境或安装项目依赖后重试。使用 `.venv/bin/python` 时尤其要确认依赖安装在同一个虚拟环境中。

### Alfresco root API 访问失败

检查 Alfresco 容器健康状态、8080 端口映射、账号密码和服务启动时间。Alfresco 初次启动可能需要等待。

### O2OA `NV_TOKEN is required`

设置 `NV_TOKEN` 环境变量后重试，不要把真实 token 写入任何文件。

### O2OA 401 / `ExceptionUnauthorized`

优先检查 token 是否过期，其次检查权限和 O2OA 服务状态。

### `seed_bad_0.json` 为什么会被拒绝

`seed_bad_0.json` 是预设非法样本，用于验证规则层或目标系统对非法结构的拒绝行为，不应解释为主链失败。

### NV_MAB 单 arm 不符合预期

检查：

- C 侧是否设置 `NV_CUR_ARM`；
- Python mutator 是否写回 `NV_JSON_ARM_USED`；
- `mutation_scope` 是否只启用了目标 arm；
- `fuzzer_stats` 中 `nv_mab_arm0_pulls`、`nv_mab_arm1_pulls`、`nv_mab_arm2_pulls` 是否符合预期。
