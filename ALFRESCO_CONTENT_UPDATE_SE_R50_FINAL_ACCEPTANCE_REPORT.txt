LESSONS LEARNED
================================================================================

1. TRACE COUNT SEMANTICS:
   Scorer trace records ALL invocations (dry-run + fuzz)
   RPC counters track only fuzz-phase invocations
   Validation logic must account for dry-run overhead

2. DRY-RUN PHASE BEHAVIOR:
   AFL++ calibrates each seed before fuzzing
   Harness executes during calibration
   Scorer invoked for dry-run bodies
   This is expected and normal operation

3. VALIDATION LOGIC DESIGN:
   Fail-closed validation must distinguish:
     - Expected trace > rpc_ok (dry-run overhead) → PASS
     - Unexpected trace < rpc_ok (lost responses) → FAIL
   Exact equality check was too strict

4. EVIDENCE TRIANGULATION:
   Multiple evidence sources confirm participation:
     - body_score_rpc_ok counter (authoritative)
     - scorer_trace.jsonl (detailed record)
     - scorer_stdout.txt (subprocess logs)

   All sources consistent after accounting for dry-run
