TECHNICAL ROOT CAUSE ANALYSIS
================================================================================

THE AFL_TARGET_ENV PROPAGATION CHAIN:

1. Runner constructs AFL_TARGET_ENV string (R47 fix: forced quotes)
2. Runner sets env["AFL_TARGET_ENV"] = "KEY1='val1' KEY2='val2' ..."
3. Runner passes env dict to subprocess.run() → AFL++ process inherits it
4. AFL++ main() calls extract_and_set_env(afl->afl_env.afl_target_env)
   (src/afl-fuzz.c line 2520, BEFORE forkserver starts at line 3513)
5. extract_and_set_env() parses AFL_TARGET_ENV and calls setenv() for each
   KEY=VALUE pair (src/afl-common.c line 896-973)
6. AFL++ forks to create target harness process
7. Harness inherits AFL++ environment (including all setenv'd variables)
8. Python harness module init runs:
   a. parse_afl_target_env() manually parses AFL_TARGET_ENV again (R48 fix)
   b. Lazy getters read variables on first use (R48 fix)

FAILURES:

R46-R47: Step 5 failed - extract_and_set_env() rejected unquoted paths
R48: Step 8a failed - Python read vars before AFL++ had parsed AFL_TARGET_ENV
     (This was WRONG diagnosis - the real issue was missing vars in step 1)
R49: Step 1 incomplete - NV_TARGET_CONFIG not in propagation list
R49B: Step 1 wrong value - NV_ENDPOINT_NAME hardcoded to wrong scenario

SUCCESS CRITERIA:
  - Variables must be in runner's AFL_TARGET_ENV construction (R49 fix)
  - Variable values must be scenario-appropriate (R49B fix)
  - Values with special chars must be quoted (R47 fix)
  - Harness must parse AFL_TARGET_ENV at module init (R48 fix, defensive)
  - Harness must use lazy getters for env vars (R48 fix, defensive)

R48 FIX WAS DEFENSIVE:
  The R48 harness changes (AFL_TARGET_ENV parser + lazy getters) were not the
  actual fix for the status_observed=false issue. The real problem was missing
  variables in the runner's AFL_TARGET_ENV construction. However, the R48
  changes remain valuable as defense-in-depth: they make the harness more
  robust to future AFL++ changes or alternative invocation patterns.
