- MINOR MIN-1 — docs/v071_real_harness_exec_seq.md §5 heads its table "NV status writers, complete" but omits verify_2_5_strict.py and tests/test_v071_exec_seq.py. Neither affects correctness (the diagnostic writes no exec_seq and degrades to legacy exactly as intended), but the completeness claim is overstated.
- MINOR MIN-2 — CLAUDE.md misattributes nv_state_probe.py as an $NV_STATUS_PATH writer. Pre-existing, outside the diff.
- MINOR MIN-3 — Allocator clamps current < 0 but has no upper clamp (os.read(fd, 64)). A corrupted 40-digit sidecar yields exec_seq=1e40; measured, that and u64-max both resolve to exec_seq=0 and fall back safely — but the namespace then stays on legacy fallback permanently until cleaned. Requires external corruption; hardening only.
- MINOR MIN-4 — With the whole status directory unwritable, write_status() raises PermissionError and the harness exits 1 with a traceback. Unchanged v0.7.0 behaviour, not caused by the allocator.
- MINOR MIN-5 — The probe re-types JSON extraction from nv_observe_security_state(); a future extraction change there wouldn't be caught.
- INFO INF-1 — The legacy seq field has zero consumers repo-wide (only the write). Sitting one line above exec_seq and permanently 1, it invites misreading. Documentation observation; keep the field.
- INFO INF-2 — Fixed .tmp staging name shared per namespace; measured 0 torn in 30,196 reads.
- INFO INF-3 — exec_seq > 2^53 loses precision in (u64)valuedouble (2^53+1 reads back as 2^53). Needs ~9×10¹⁵ executions.
- INFO INF-4 — Worth knowing operationally: urllib honours http_proxy, and this machine's no_proxy uses 127.*, a glob urllib doesn't match. My first run had every local request answered 502 and recorded as 5xx. Allocation stayed correct, but a campaign run in a proxied shell would record fabricated 5xx behaviour.
