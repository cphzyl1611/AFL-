================================================================================
LESSONS LEARNED
================================================================================

1. Environment Variable Propagation is Critical

   The R40 failure highlights that environment variable propagation through
   subprocess chains is a critical failure point. Even when the harness code
   is correct, missing environment variables cause silent initialization failures.

   Recommendation: Add environment variable validation to harness startup:
     - Check for required NV_* variables
     - Fail fast with clear error message if missing
     - Log environment snapshot to evidence/ directory

2. Stderr Capture is Essential for Diagnosis

   The R40 harness failure produced no diagnostic evidence because stderr was
   not captured. This made root cause determination difficult and time-consuming.

   Recommendation: Always capture harness stderr to evidence/:
     - Redirect AFL++ harness stderr to evidence/harness_stderr.txt
     - Preserve exception traces for postmortem analysis
     - Include stderr in artifact contract validation

3. Launch Configuration Validation is Necessary

   The R40 campaign consumed the ONE authorized real attempt without providing
   any scientific value because launch configuration was not validated before
   launch.

   Recommendation: Add pre-launch configuration validation:
     - Verify all required environment variables are set
     - Test harness invocation with sample input before AFL++ launch
     - Fail fast if harness does not produce status file on test run

4. Manual Reproduction Tests are Invaluable

   The manual harness test (feeding seed.http with correct environment) was
   the KEY diagnostic that proved the harness code was correct and identified
   the launch configuration defect.

   Recommendation: Build manual reproduction capability into validation workflow:
     - Create standalone harness test script
     - Use exact seed input from AFL++ queue
     - Compare manual vs AFL++ results for discrepancies

5. R39 Local Validation Remains Valid Despite R40 Failure

   The R40 failure does NOT invalidate the R39 local validation (352 test cases).
   The R40 failure is completely unrelated to the R39 Protocol V2 repair.

   Confirmation: Local tests provide PARTIAL assurance but cannot replace
   real-world validation. Production deployment requires successful real
   validation, not just local tests.
