R44B ROOT CAUSE (PROVEN)
-------------------------

ROOT_CAUSE_CLASSIFICATION: AUTH_SETUP_FAILURE
ROOT_CAUSE_MECHANISM: MISSING_AFL_TARGET_ENV_DECLARATION

Exact Mechanism:
AFL++ does NOT automatically propagate arbitrary environment variables from its
process environment to the target harness subprocess. This is by design for
security isolation. Custom application variables (like ALFRESCO_USER and
ALFRESCO_PASS) must be explicitly declared via AFL_TARGET_ENV, which triggers
AFL++'s extract_and_set_env() function to parse and propagate them.

Evidence Chain:
1. Runner correctly passed credentials to AFL++ via subprocess.run(env=env)
2. Prelaunch validation verified credentials were present (launch_returncode=0)
3. AFL++ process received credentials in its environment
4. AFL++ did NOT propagate credentials to harness (no AFL_TARGET_ENV set)
5. Harness os.getenv("ALFRESCO_USER") returned None
6. Harness raised RuntimeError at line 1138 during apply_auth_headers()
7. Unhandled exception prevented write_status() call

# the target harness for security isolation. Custom application variables
# must be explicitly declared via AFL_TARGET_ENV, which extract_and_set_env()
# parses at AFL++ startup (src/afl-common.c:896-973).
#
# The prelaunch validation above ensures ALFRESCO_USER and ALFRESCO_PASS are
# present in child_env (and thus in env), but they will not reach the harness
# subprocess unless explicitly listed in AFL_TARGET_ENV.
#
# Use shlex.quote() for shell-safe quoting in case credentials contain spaces
# or special characters.
import shlex

pass_quoted = shlex.quote(env["ALFRESCO_PASS"])
env["AFL_TARGET_ENV"] = f"ALFRESCO_USER={user_quoted} ALFRESCO_PASS={pass_quoted}"
