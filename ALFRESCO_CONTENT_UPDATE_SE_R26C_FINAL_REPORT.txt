SCIENTIFIC FINDINGS
================================================================================

1. COUNTER SEMANTICS:
   The nv_valid_cnt counter is MISLEADING in body_only_mode. It counts harness
   exit code 0, which includes BOTH:
     a) Validation rejects that wrote status (Path A)
     b) HttpBodyAdapterError early returns that did NOT write status (Path B)

2. AFL++ MUTATION BEHAVIOR:
   Standard bit-flipping and byte mutations easily corrupt HTTP envelope:
     - Removing delimiter bytes (\r\n\r\n → \r\n\n or \r\r\n)
     - Mangling request line (PUT /path → PU /path)
     - Truncating before delimiter

3. EXEC_SEQ MONOTONICITY CONTRACT:
   The file-based exec_seq allocation via next_exec_seq() and flock() is
   correct, but only called from write_status(). When write_status() is
   bypassed, exec_seq monotonicity breaks.

4. RETRY LOOP TIMEOUT:
   500 attempts × 2ms = 1 second total. This is sufficient for normal status
   writes but will always timeout when write_status() is never called.

5. LEDGER DISCREPANCY:
   Execution ledger has 5 records but fuzzer_stats shows execs_done=6. The
   missing record suggests one execution never reached the journal point,
   possibly due to fuzzer initialization or calibration edge case.
