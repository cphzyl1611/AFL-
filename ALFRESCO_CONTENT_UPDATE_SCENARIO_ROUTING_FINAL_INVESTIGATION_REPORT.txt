  [ 2] scenario_multipart_upload      =   0.000000
  [10] invalid_type_count             =   1.000000  ← CRITICAL

Actual Extractor Dispatch:
  The seed body (JSON properties payload) triggered METADATA extraction,
  setting dim[0]=1.0. This is semantically correct for the seed content
  (it IS metadata), but INCORRECT for the content_update scenario contract
  (which expects text content, triggering dim[1]=1.0).

Root Cause of Wrong Extraction:
  The extractor makes dispatch decisions based on BODY CONTENT, not on
  SCENARIO LABEL. The JSON properties payload naturally triggers metadata
  extraction because it is a JSON object with a "properties" field.

Extraction Flow for Frozen Seed:
  1. Extractor receives raw body bytes: {"properties":{...}}
  2. Detects JSON structure
  3. Detects "properties" field
  4. Dispatches to extract_metadata_features()
  5. Sets scenario_metadata_update=1.0 (dim[0])
  6. Computes invalid_type_count=1.0 (dim[10]) due to missing "name" field

Expected Extraction for Content_Update Scenario:
  1. Extractor should receive plain text body
  2. No JSON structure detected
  3. Dispatches to extract_content_features()
  4. Sets scenario_text_content_update=1.0 (dim[1])
  5. Computes text features (byte_length, char_length, entropy, etc.)

SEED_BODY_TRIGGERS_WRONG_EXTRACTOR = YES

PRIMARY ROOT CAUSE: B — THRESHOLD MISMATCH / TRAINING DISTRIBUTION MISMATCH

Detailed Analysis:

The canonical SE model (sefanogan_es_reference) was trained on a distribution
where feature dimension 10 (invalid_type_count) had ZERO VARIANCE across all
9 training samples (all had value 0.0). The normalization layer's standard
deviation for this dimension is effectively zero (std[10] = 1e-8).

When scoring the frozen seed with invalid_type_count=1.0 under metadata
extraction, normalization explodes:
  z[10] = (1.0 - 0.0) / 1e-8 = 10^8

This z-score is 10 MILLION times larger than typical outlier thresholds,
causing catastrophic reconstruction error and a score of ~100 million.

When scoring the same seed under hypothetical text extraction, the seed body
(JSON payload) is still incompatible with the SE model's text content training
samples (real prose/logs/documents), producing a score of 11.32 (8.8× above
threshold).

ROOT CAUSE STATEMENT:
  The frozen content_update seed is a JSON properties payload that is
  structurally incompatible with the SE training distribution under BOTH
  metadata_update AND text_content_update scenarios. The SE model learned
  only metadata payloads with zero invalid_type_count and only text content
  from real documents, making it unable to score a JSON metadata payload
  as either scenario.

SECONDARY BUGS: A+C — IMPLEMENTATION BUGS (NOT BLOCKING)

Bug A: RPC protocol discards endpoint_name (nv_body_valid.py:234)
  Type:         Implementation bug
  Fixability:   TDD repair possible (remove "del endpoint_name")
  Impact:       Prevents scenario routing to scorer
  Blocking:     NO (seed rejects under both scenarios anyway)

Bug B: Scorer has no scenario dispatch (nv_valid_server_mock.py)
  Type:         Architectural gap
  Fixability:   Feature implementation needed (add scenario dispatch logic)
  Impact:       Even if endpoint_name passed, no dispatch occurs
  Blocking:     NO (seed rejects under both scenarios anyway)

BUGS_ARE_BLOCKING = NO

Justification:
  Offline rescoring under BOTH scenarios (metadata and text extraction) proved
  the seed rejects in both cases. Fixing the routing bugs would change which
  extraction function is called, but the seed would still reject because:
    - Metadata extraction: zero-variance catastrophe (score 100M)
    - Text extraction: JSON-vs-text mismatch (score 11.32)

TDD_REPAIR_APPLICABLE = NO

Justification:
  The primary root cause is a training distribution defect (Classification B),
  which cannot be fixed by code changes. The SE model must be retrained with
  corrected training data, or the seed must be replaced with a compatible one.

  The secondary bugs (A+B) CAN be fixed via TDD, but fixing them would NOT
  resolve the SE failure for this frozen seed. They should be fixed
  independently to improve the system's scenario routing capabilities for
  future experiments, but they are not part of the critical path for this
  content_update validation.

FINAL CLASSIFICATION:
  PRIMARY:   B (Canonical spec incompatibility — seed/model mismatch)
  SECONDARY: A+C (Implementation bugs — fixable but not blocking)
