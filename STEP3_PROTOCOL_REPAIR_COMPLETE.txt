CONTENT_UPDATE RAW TEXT SEMANTICS PRESERVED
================================================================================

LOGICAL_CONTENT_UPDATE_BODY_REMAINS_RAW_TEXT = YES

Reasoning:
- The content_update scenario body is raw UTF-8 text (not JSON)
- Protocol V2 encoding: base64(raw_text_bytes)
- Scorer decoding: base64_decode() → raw_text_bytes
- Model receives: identical bytes to what AFL++ extracted from HTTP body
- NO semantic transformation of the text content itself

Example flow:
  1. AFL++ receives HTTP request with body: "这是一段测试文本..." (raw UTF-8)
  2. AFL++ extracts body bytes: b'\xe8\xbf\x99\xe6\x98\xaf...'
  3. AFL++ base64-encodes: "6L+Z5piv5LiA5q6177yM55So5LqO6aqM..."
  4. Scorer base64-decodes: b'\xe8\xbf\x99\xe6\x98\xaf...'
  5. Model receives: identical bytes from step 2

The base64 encoding is ONLY for binary-safe transport in the JSON envelope.
The logical content remains raw text at both endpoints.
