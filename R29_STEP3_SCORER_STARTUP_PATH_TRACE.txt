ARCHITECTURAL NOTE
------------------
The scorer socket path is dynamic (contains run_root timestamp). It cannot
be known when build_task_payload() is called because the scorer hasn't been
started yet. The path is created later by ScorerLifecycleManager.

This means build_task_payload() cannot populate validity_endpoint. Instead,
the runner must:
1. Call build_task_payload() to get initial task dict
2. Start scorer and get socket path
3. Add validity_endpoint to task dict
4. Write final task dict to task.json

OR: Change build_task_payload() signature to accept optional validity_endpoint
parameter that the caller provides after starting the scorer.

  Line 3126: task = build_task_payload(...)  # No endpoint yet

  Line 3165: scorer_manager.start()           # Socket created AFTER write

The scorer startup path is correctly implemented EXCEPT for one missing step:
