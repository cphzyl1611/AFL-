## Problem Statement

### Context
The NV fuzzing framework supports model-comparison mode, which requires scorer participation evidence:
1. `nv_body_valid_stats.json` showing `body_score_rpc_ok > 0`
2. `scorer_trace.jsonl` containing backend evidence
3. `validate_model_comparison_participation()` returning verdict=PASS

### Issue
The metadata_update endpoint (body_only_mode=1) produced valid scorer participation evidence, but content_update (body_only_mode=0, full HTTP with text/plain body) did not invoke the scorer at all. This prevented content_update from participating in model-comparison validation.

### Root Cause
The scorer invocation code path existed only in the body_only_mode=1 branch (lines 1012-1054). The body_only_mode=0 branch (lines 1056-1110) had no scorer invocation, causing content_update executions to skip model-comparison validation entirely.

**File**: nv_http_harness.py

**Implementation** (39 lines):
```python
# Model-comparison scorer invocation for full-HTTP mode (body_only_mode=0)
# This enables content_update to participate in model-comparison validation
# by invoking the scorer RPC with raw body bytes, mirroring the
# body_only_mode=1 flow but without JSON rule validation.
score_endpoint = os.getenv("NV_BODY_SCORE_ENDPOINT", "").strip() or None
if score_endpoint and body:
    score_threshold = None
    sth = os.getenv("NV_BODY_SCORE_THRESHOLD", "").strip()
    if sth:
        try:
            score_threshold = float(sth)
        except Exception:
            score_threshold = None

    # Derive endpoint_name from environment or config (same as body_only_mode=1)
    endpoint_name = os.getenv("NV_ENDPOINT_NAME", str(cfg.get("default_endpoint", "")).strip())
    if not endpoint_name:
        endpoint_name = "unknown"

    from nv_body_valid import rpc_score_unix
    rpc_ok, score = rpc_score_unix(score_endpoint, endpoint_name, body)

    if rpc_ok:
        bump_body_valid_stat("body_score_rpc_ok")
        if score_threshold is not None and score is not None and score >= score_threshold:
            bump_body_valid_stat("body_score_reject")
            write_status(
                method,
                path,
                0,
                body_hash16=int(zlib.crc32(body) & 0xffff),
                validation_reject=1,
            )
            return 0
        else:
            bump_body_valid_stat("body_score_pass")
    else:
        bump_body_valid_stat("body_score_rpc_fail")
```

**Key Design Decisions**:
1. Placement after path sanitization ensures valid method/path before scorer invocation
2. endpoint_name derivation matches body_only_mode=1 pattern for consistency
3. Raw body bytes passed to scorer (no JSON normalization needed for text/plain)
4. Stats counter updates mirror body_only_mode=1 semantics
5. Early return on threshold rejection preserves validation contract

## Technical Details

### Scorer RPC Protocol
- **Transport**: Unix domain socket (AF_UNIX, SOCK_STREAM)
- **Request Format**: 4-byte little-endian length prefix + JSON payload
- **Response Format**: Plain float as ASCII text (`"0.050000\n"`)
- **Client**: `nv_body_valid.rpc_score_unix()`
- **Server**: `nv_valid_server_mock.py` (development) / production scorer (deployment)

### Stats Counters
Updated in `nv_body_valid_stats.json`:
- `body_score_rpc_ok`: Successful scorer invocations
- `body_score_rpc_fail`: Failed scorer invocations
- `body_score_pass`: Bodies accepted by scorer (score < threshold)
- `body_score_reject`: Bodies rejected by scorer (score >= threshold)
- `body_rule_pass`: Bodies passing rule-based validation (body_only_mode=1 only)
- `body_rule_reject`: Bodies failing rule-based validation (body_only_mode=1 only)

### Execution Paths
**body_only_mode=0 (content_update)**:
1. parse_http_seed(data) → method, path, headers, body
2. Path sanitization (method/path validation)
3. **[NEW]** Scorer invocation (if NV_BODY_SCORE_ENDPOINT configured)
4. Context placeholder injection (legacy)
5. HTTP request execution
6. State probe update

**body_only_mode=1 (metadata_update)**:
1. Derive method/path from named endpoint
2. Rule-based validation (nv_body_valid.body_validate)
3. Scorer invocation (if NV_BODY_SCORE_ENDPOINT configured)
4. JSON body normalization
5. HTTP request execution
6. State probe update

### Debugging Notes

**Issue 1: UnboundLocalError for endpoint_name**
- **Symptom**: `UnboundLocalError: cannot access local variable 'endpoint_name'`
- **Root Cause**: Initial scorer invocation code referenced `endpoint_name` but never defined it
- **Fix**: Added endpoint_name derivation before rpc_score_unix call (lines 1086-1088)

**Issue 2: Mock Scorer Protocol Mismatch**
- **Symptom**: `body_score_rpc_ok: 0` despite scorer invocation visible in test
- **Root Cause**: MockScorerServer sent JSON response but rpc_score_unix expects plain float
- **Investigation**: Read nv_valid_server_mock.py line 112 to confirm real protocol
- **Fix**: Changed mock response from `json.dumps({"score": score})` to `f"{score:.6f}\n"`
