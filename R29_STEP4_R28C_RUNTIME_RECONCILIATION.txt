SOURCE CODE ASSUMPTION VIOLATED
--------------------------------

AFL's C code assumes:
  "If a run is configured for model comparison, task.json will contain
   a validity_endpoint field pointing to a live Unix socket."

This assumption is documented by:
1. No fallback logic when validity_endpoint is NULL
2. No environment variable alternative (AFL doesn't check NV_BODY_SCORE_ENDPOINT)
3. Early-return design: if (!ep || !*ep) return 0.0;

The runner VIOLATES this assumption by:
1. Starting scorer process ✓
2. Setting NV_BODY_SCORE_ENDPOINT environment variable ✓
3. Writing task.json WITHOUT validity_endpoint ✗
4. Launching AFL which only reads task.json, not environment ✗

WHY THIS WASN'T CAUGHT EARLIER
-------------------------------

1. The runner code has TWO parallel validity mechanisms:
   - Environment variables (NV_BODY_SCORE_ENDPOINT, etc.)
   - Task.json fields (validity_endpoint)

2. The harness (nv_http_harness.py) reads from environment
   The fuzzer (afl-fuzz) reads from task.json

3. No integration test validates that AFL can actually reach the scorer
   in model comparison mode

4. The build_task_payload() function signature accepts validity_backend
   but doesn't document that it's unused for validity_endpoint

ARCHITECTURAL DEBT
------------------

The split between environment variables and JSON config creates
coordination failures:

- Harness uses: NV_STATUS_PATH, NV_BODY_RULES, NV_BODY_SCORE_ENDPOINT
- AFL uses: task.json fields including validity_endpoint
- Runner must keep both in sync but has no type-safe contract

The validity_backend parameter to build_task_payload() is misleading:
it's validated but not used, suggesting it controls something (which
it doesn't).

CONCLUSION
----------

R28C runtime did not match AFL's expectations because:

1. The runner launched scorer and set environment variables
2. But AFL doesn't read environment variables for scorer path
3. AFL only reads task.json, which lacked validity_endpoint
4. build_task_payload() receives validity_backend but doesn't populate
   validity_endpoint (because socket path not available yet)
5. No code after scorer startup updates task.json with the socket path
6. AFL started with NULL validity_endpoint and skipped all scorer calls

The defect is an orchestration gap: task.json is finalized before the
scorer socket exists, and never updated afterwards.
