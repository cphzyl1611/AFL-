================================================================================
EXECUTIVE SUMMARY
================================================================================

R39 failed due to a PROTOCOL VERSION MISMATCH between AFL++ and the scorer
subprocess. AFL++ sends raw HTTP request bytes (Protocol v1) while the scorer
expects JSON-wrapped payloads (Protocol v2). This caused all 56 scoring
attempts to fail with JSONDecodeError, leaving AFL++ blocked indefinitely
waiting for responses that never came.

The failure was silent because:
1. Scorer error output was directed to subprocess.PIPE (never read by parent)
2. AFL++ has no timeout on recv() system call (line 838 of afl-fuzz-run.c)

R38C verification passed because it used Python harness (nv_body_valid.py)
which correctly implements Protocol v2, while R39 used AFL++ C code which
implements Protocol v1.

WHY R38C VERIFICATION PASSED

R38C used Python harness path (nv_body_valid.py) which implements Protocol v2:

nv_body_valid.py lines 240-279:
  - Constructs JSON envelope: {"scenario": "...", "endpoint": "...", "body": "base64..."}
  - Encodes body as base64
  - Sends [4-byte length][JSON envelope]
  - Scorer recv_one() successfully parses JSON
  - predict_score_from_body() receives correct scenario and body-only bytes
  - Scoring succeeds

R39 used AFL++ C code path (afl-fuzz-run.c) which implements Protocol v1:
  - Sends [4-byte length][raw HTTP request]
  - No JSON envelope, no base64 encoding, no scenario field
  - Scorer recv_one() fails to parse, uses fallback
  - predict_score_from_body() receives wrong scenario and HTTP-with-headers
  - json.loads() fails on "PUT /alfresco/..." → JSONDecodeError

The protocol mismatch was not detected because:
1. R38C verification only tested Python harness path
2. AFL++ RPC path had no unit tests
3. No integration test exercised AFL++ → scorer RPC

SECONDARY DEFECTS AMPLIFYING IMPACT
================================================================================

1. No timeout on AFL++ recv() (src/afl-fuzz-run.c line 838)
   - Python harness has 1-second timeout (nv_body_valid.py line 245)
   - C code has NO timeout
   - Single failed RPC blocks entire fuzzing campaign indefinitely

2. Subprocess stderr/stdout to PIPE, never read
   - Line 2765-2771 of run_alfresco_bounded_feedback.py
   - stdout=subprocess.PIPE, stderr=subprocess.PIPE
   - Parent never reads from PIPE
   - All error messages lost (scorer's traceback.print_exc())

3. Scorer exception handler continues loop without responding
   - Lines 340-342 catch exception, print error, continue
   - No error response sent to client
   - Client has no way to distinguish "still processing" from "failed"

4. Protocol version negotiation absent
   - No version field in protocol
   - No capability detection
   - Silent incompatibility
